# 部署文档：在全新 Ubuntu + NVIDIA GPU 主机上部署多模型 Agent

本文面向这样一台目标主机：

- 全新安装的 Ubuntu（22.04 / 24.04 LTS），尚未安装本项目的任何依赖；
- 有一块 NVIDIA GPU，已装或未装驱动；
- **还没有部署任何大模型服务，也没有现成的 API 地址**。

因此本文包含两段路程：先把大模型服务跑起来（第 5 章），再把 Agent 接上去（第 6 章）。如果 GPU 上新模型还没跑起来，Agent 无论怎么配都无法对话，所以顺序不能颠倒。

整体路线：

```text
1. 拉取代码 → 2. Python 环境 → 3. 系统依赖 → 4. 校验代码可运行
     → 5. 部署本地推理服务（vLLM）→ 6. 改配置指向它 → 7. 启动并验证
```

---

## 0. 名词与约定

| 名称 | 含义 |
| --- | --- |
| Agent | 本项目，负责对话编排、工具调用、Token 统计 |
| 推理服务 | vLLM（本文示例），真正加载模型、提供 OpenAI 兼容 API |
| `models.json` | Agent 的模型配置，**会提交到 Git**，不含真实地址 |
| `models.local.json` | 本机覆盖配置，**不提交**，放真实地址与密钥 |

本文命令默认使用普通用户 + `sudo`，项目目录统一为 `~/multi-model-agent`。

## 1. 从 Git 仓库克隆到本地

### 1.1 安装 Git

```bash
sudo apt update
sudo apt install -y git curl ca-certificates
git --version
```

### 1.2 克隆项目

```bash
cd ~
git clone https://github.com/Deepsealeviathan/Jn-Agent.git multi-model-agent
cd multi-model-agent
git checkout 1.0
```

> 仓库默认分支为 `1.0`。克隆后若已在 `1.0`，`git checkout` 会提示 Already on '1.0'，属正常。

```bash
ls -la
git log --oneline -3
```

应能看到 `agent.py`、`server.py`、`ui.html`、`models.json`、`Doc/` 等文件。

## 2. 准备 Python 环境

### 2.1 版本要求

项目**只使用 Python 标准库**，没有第三方运行时依赖（无 `requirements.txt`）。但读取 TOML 格式的密钥文件需要 `tomllib`，因此要求：

**Python 3.11 或更高版本。**

Ubuntu 24.04 自带 Python 3.12，可直接使用；Ubuntu 22.04 自带 3.10，需要升级。

### 2.2 安装 Python（按系统版本选择）

Ubuntu 24.04：

```bash
sudo apt install -y python3 python3-venv python3-pip
python3 -V
```

Ubuntu 22.04（自带 3.10，需装 3.12）：

```bash
sudo apt install -y software-properties-common
sudo add-apt-repository -y ppa:deadsnakes/ppa
sudo apt update
sudo apt install -y python3.12 python3.12-venv
python3.12 -V
```

> 若 `add-apt-repository` 报错，先执行 `sudo apt install -y software-properties-common`。

### 2.3 关于虚拟环境

Agent 本身**不需要**虚拟环境，系统 Python 直接跑即可。但建议建一个，避免日后的其他项目互相污染：

```bash
cd ~/multi-model-agent
python3 -m venv .venv
source .venv/bin/activate
python -V
```

> Ubuntu 24.04 受 PEP 668 保护，直接 `pip install` 到系统环境会被拒绝（`externally-managed-environment`）。本项目不需要装任何包，所以不受影响；如果后续想装工具，请先激活虚拟环境。

### 2.4 验证 Agent 可用

```bash
cd ~/multi-model-agent
python3 -m py_compile agent.py server.py && echo "语法检查通过"
python3 agent.py --list-models
```

此时因为还没有推理服务，`--list-models` 会显示密钥缺失或模型不可用，**这是正常现象**，第 6 章会解决。

## 3. 准备 GPU 与推理服务依赖

### 3.1 检查 GPU 驱动

```bash
nvidia-smi
```

- 能输出显卡型号、显存、驱动版本 → 跳到 3.3；
- 提示 `command not found` → 继续 3.2。

### 3.2 安装 NVIDIA 驱动（仅在缺失时）

```bash
sudo apt update
sudo apt install -y ubuntu-drivers-common
ubuntu-drivers devices          # 查看推荐驱动
sudo ubuntu-drivers autoinstall # 安装推荐版本
sudo reboot
```

重启后再次执行 `nvidia-smi` 确认。

### 3.3 安装运行依赖

```bash
sudo apt install -y build-essential pkg-config libssl-dev
```

### 3.4 确认显存，决定模型规模

`nvidia-smi` 输出中的 `MiB` 总值决定能跑多大模型（粗估，含 KV Cache 余量）：

| 显存 | 建议模型规模 | 示例 |
| --- | --- | --- |
| 8 GB | 1.5B–4B（4bit 量化） | Qwen3-4B-Instruct |
| 16 GB | 7B–8B（FP16 或 4bit） | Qwen3-8B |
| 24 GB | 7B–14B（FP16） | Qwen3-14B-Instruct |
| 48 GB+ | 32B 及以上 | Qwen3-32B |

> 显存不足时 vLLM 会在启动阶段直接报 OOM，不会静默降级。先选小模型跑通，再换大的。

## 4. 部署本地大模型服务（vLLM）

本章把 `http://localhost:8000/v1` 变成可用的 OpenAI 兼容接口。

### 4.1 创建独立环境

推理服务依赖较重，务必与 Agent 分开：

```bash
python3 -m venv ~/vllm-env
source ~/vllm-env/bin/activate
pip install -U pip
```

### 4.2 安装 vLLM

```bash
pip install vllm
```

> 安装包体积较大（含 PyTorch），请预留至少 10 GB 磁盘空间，并保证网络稳定。
>
> 若下载中断，可加国内镜像重试：
> `pip install vllm -i https://pypi.tuna.tsinghua.edu.cn/simple`

### 4.3 启动服务

以 Qwen3-8B 为例：

```bash
source ~/vllm-env/bin/activate

vllm serve Qwen/Qwen3-8B-Instruct \
  --host 0.0.0.0 \
  --port 8000 \
  --served-model-name qwen3-8b \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.90
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--served-model-name` | 对外暴露的模型名，**必须与 Agent 配置里的 `model` 一致** |
| `--max-model-len` | 最大上下文长度，**必须与配置里的 `max_context` 一致或更小** |
| `--gpu-memory-utilization` | 显存占用上限，默认 0.9 |

首次启动需要从 HuggingFace 下载权重，耗时取决于网速。

> 网络受限时可先设镜像：`export HF_ENDPOINT=https://hf-mirror.com` 后再启动。

### 4.4 验证推理服务

新开一个终端：

```bash
curl http://localhost:8000/v1/models
```

应返回包含 `qwen3-8b` 的 JSON。再测一次对话：

```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3-8b",
    "messages": [{"role": "user", "content": "你好"}],
    "max_tokens": 64
  }'
```

返回含 `choices[0].message.content` 即成功。

### 4.5 记录两个关键值

后续配置需要用到：

- **API 地址**：`http://localhost:8000/v1`
- **模型名**：`qwen3-8b`（即 `--served-model-name` 的值）

### 4.6 让 vLLM 常驻（可选）

临时用 `nohup`：

```bash
source ~/vllm-env/bin/activate
nohup vllm serve Qwen/Qwen3-8B-Instruct \
  --host 0.0.0.0 --port 8000 \
  --served-model-name qwen3-8b \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.90 \
  > ~/vllm.log 2>&1 &
```

查看日志：`tail -f ~/vllm.log`；停止：`pkill -f "vllm serve"`。

> 生产环境建议改用 systemd 托管，见附录 A。

## 5. 修改 Agent 配置，把 API 地址接进去

这里有一个**设计要点**必须先说明：

- `models.json` 会提交到 Git，所以里面只写 `localhost` 这类脱敏地址；
- 真实地址写在 `models.local.json`，该文件已在 `.gitignore` 中，不会被提交；
- 程序启动时会自动把 `models.local.json` **深度合并**到 `models.json` 之上，因此无需改动受版本控制的文件。

### 5.1 创建本机覆盖配置

在**项目根目录**创建 `models.local.json`：

```bash
cd ~/multi-model-agent
nano models.local.json
```

填入以下内容：

```json
{
  "providers": {
    "deepseek": {
      "base_url": "http://localhost:8000/v1",
      "api_key": "EMPTY"
    }
  },
  "models": {
    "deepseek": {
      "model": "qwen3-8b",
      "display": "Qwen3 8B (vLLM 本地)",
      "max_context": 32768,
      "max_tokens": 4096
    }
  }
}
```

字段对应关系：

| 字段 | 应填内容 | 对应 vLLM 参数 |
| --- | --- | --- |
| `base_url` | `http://localhost:8000/v1` | `--port 8000` |
| `api_key` | `EMPTY`（占位，见 5.3） | 无需，vLLM 不校验 |
| `model` | `qwen3-8b` | `--served-model-name` |
| `max_context` | `32768` | `--max-model-len` |

> **为什么复用 `deepseek` 这个 provider 名？**
> 因为它已经是 `default_model` 指向的提供方，且 `protocol` 为 `openai`，与 vLLM 完全兼容。复用可避免额外改动 `default_model`。若你希望语义更清晰，也可以新增 provider，见 5.5。

### 5.2 清理会产生冲突的字段

`models.json` 中 DeepSeek 原配置带有思考模式开关：

```json
"enable_thinking_body": {"chat_template_kwargs": {"enable_thinking": true}},
"disable_thinking_body": {"chat_template_kwargs": {"enable_thinking": false}}
```

这两个字段会被原样发给推理服务。Qwen3 等较新模型的 chat template 支持 `enable_thinking` 的含义；但如果你的模型不认识这个参数，可能返回 400。

如果遇到这类报错，在 `models.local.json` 中把它们置为 `null` 即可：

```json
{
  "providers": {
    "deepseek": {
      "base_url": "http://localhost:8000/v1",
      "api_key": "EMPTY",
      "enable_thinking_body": null,
      "disable_thinking_body": null
    }
  }
}
```

> **注意：必须用 `null`，不能写成 `{}`。**
> 配置合并采用深度合并，空对象 `{}` 会与原有内容递归合并，结果是**什么都没删掉**，参数照旧发送。只有 `null` 才是替换整个值。
>
> 置为 `null` 后请求体中不再出现 `chat_template_kwargs`，同时 WebUI 的「深度思考」开关会隐藏——该开关依赖这两个字段同时存在才会显示。

### 5.3 关于 api_key 的说明

Agent 在**发起请求时**要求 provider 必须有可用密钥，否则直接报错：

```text
模型提供方 'deepseek' 没有可用的 API Key。请设置api_key 字段，或在 models.json 的 providers.deepseek 里填写 api_key。
```

但 vLLM 默认不校验密钥。因此按 5.1 填一个占位值 `EMPTY` 即可，Agent 会发送 `Authorization: Bearer EMPTY`，vLLM 直接忽略。

三种等价的填法（任选其一）：

| 方式 | 写法 | 适用场景 |
| --- | --- | --- |
| 配置内占位 | `"api_key": "EMPTY"` | 最简单，推荐 |
| 环境变量 | 先 `export DEEPSEEK_API_KEY=EMPTY` | 不想把值写进文件 |
| 单独密钥文件 | 用 `api_key_from` 指向文件 | 需要动态刷新密钥 |

> **安全提醒**：如果 vLLM 用 `--api-key` 设了真实密钥，这里就必须填那个真实值，且应放在 `models.local.json` 而不是 `models.json`。

### 5.4 验证配置已生效

```bash
cd ~/multi-model-agent
python3 agent.py --list-models
```

密钥列应显示 `✓ config`，上下文列应显示你配置的上下文长度。

再测一次真实对话（推荐用这种方式验证，理由见下）：

```bash
python3 agent.py -m deepseek "回复：OK"
```

> **注意 `--ping` 的行为**：它会依次测试 `models.json` 中的**全部 6 个模型别名**，且 `-m` 参数对它无效。在只部署了本地模型的机器上，Kimi 等未配置的别名必然显示 `✗`，属正常现象——只要目标模型那一行是 `✓` 即可。
>
> 若只想验证本地模型，用上面的单次对话命令，或加 `--config` 指向一份只含本地模型的精简配置。

### 5.5 （可选）新增独立 provider

希望配置语义更清晰时，可以不动 `deepseek`，另加一个 provider：

`models.local.json`：

```json
{
  "default_model": "local",
  "providers": {
    "vllm": {
      "protocol": "openai",
      "base_url": "http://localhost:8000/v1",
      "api_key": "EMPTY"
    }
  },
  "models": {
    "local": {
      "provider": "vllm",
      "model": "qwen3-8b",
      "display": "本地 vLLM",
      "max_context": 32768,
      "max_tokens": 4096
    }
  }
}
```

`default_model` 会被覆盖为 `local`，启动后默认即用它。

### 5.6 配置项速查

`models.json` 中与本部署相关的全局字段：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `default_model` | `deepseek` | 默认模型别名 |
| `max_tool_steps` | `20` | 单轮最多工具调用步数 |
| `shell_timeout` | `120` | shell 工具超时秒数 |
| `context_compress.threshold_tokens` | `190464` | 上下文超 186K 自动压缩 |
| `usage_log` | `~/.multi-model-agent/usage.jsonl` | Token 日志路径 |

上下文压缩默认开启，186K 阈值对小模型（如 32K 上下文）没有意义，会由上游先报错。使用小模型时建议同步调低：

```json
{
  "context_compress": {
    "enabled": true,
    "threshold_tokens": 24576
  }
}
```

> 阈值应明显小于 `max_context`，否则模型还没等到压缩就先超限了。

## 6. 启动与使用

### 6.1 命令行模式

```bash
cd ~/multi-model-agent
python3 agent.py
```

进入交互界面后直接输入问题。常用命令：

| 命令 | 作用 |
| --- | --- |
| `/models` | 查看模型与密钥状态 |
| `/model <别名>` | 切换模型 |
| `/usage` | 查看本次会话与历史 Token |
| `/context` | 查看当前上下文占用 |
| `/auto on` | 关闭工具执行确认（谨慎） |
| `/exit` | 退出 |

单次调用：

```bash
python3 agent.py "用一句话解释什么是向量数据库"
```

历史统计：

```bash
python3 agent.py --stats
```

### 6.2 Web 模式

```bash
cd ~/multi-model-agent
python3 server.py --host 0.0.0.0 --port 8010
```

启动后终端会打印带令牌的访问地址：

```text
多模型 Agent 服务已启动 · 默认模型 deepseek
令牌来源：/home/<用户>/.multi-model-agent/server.token
本机访问：http://localhost:8010/?token=<TOKEN>
```

用浏览器打开该地址即可。令牌首次启动自动生成，保存在 `~/.multi-model-agent/server.token`。

> 服务端默认不打印局域网 IP，便于分享日志；其他机器访问时请自行用 `hostname -I` 查本机地址。

#### 关于 `--auto`

`server.py --auto` 只决定**新会话的初始权限档位**。WebUI 每次请求都会带上页面「操作权限」的当前选择并将其覆盖，因此：

- 页面选「必要时询问」（默认）：删除、软件安装、`sudo` 才确认，其余直接执行；
- 页面选「完全自动」：不询问，直接执行所有操作；
- 页面选「始终询问」：每一步文件读写与命令都要确认。

也就是说，即使启动时加了 `--auto`，用户在页面里选择「必要时询问」后，危险操作依然会被拦截。**不要指望 `--auto` 作为安全边界，真正的边界是页面上的档位选择。**

> 建议不要在面向多人的部署中默认使用「完全自动」。该档位下模型可自由执行任意命令。

### 6.3 把服务放到后台常驻

```bash
cd ~/multi-model-agent
nohup python3 server.py --host 0.0.0.0 --port 8010 > ~/agent.log 2>&1 &
echo $! > ~/.multi-model-agent/server.pid
```

停止：`kill $(cat ~/.multi-model-agent/server.pid)`

### 6.4 放行防火墙（仅需外部访问时）

```bash
sudo ufw allow 8010/tcp
sudo ufw allow 8000/tcp   # 仅在本机之外也要直连 vLLM 时才需要
sudo ufw status
```

> **重要**：`8000` 是 vLLM 端口，默认无鉴权，不要暴露到公网。Agent 的 `8010` 有令牌保护。

## 8. 常见问题

### 8.1 `模型提供方 'xxx' 没有可用的 API Key`

未填 `api_key`。vLLM 不校验密钥，但 Agent 要求字段存在，按 5.1 填 `"api_key": "EMPTY"`。

### 8.2 `HTTP 404` 或 `model not found`

`models.local.json` 里的 `model` 与 vLLM 的 `--served-model-name` 不一致。核对两者拼写。

### 8.3 `HTTP 400`，提示上下文超长

`max_context` 大于 vLLM 的 `--max-model-len`。把配置里的 `max_context` 调到不超过该值，并同步调低 `context_compress.threshold_tokens`。

### 8.4 vLLM 启动报显存不足（OOM）

换更小模型、降低 `--gpu-memory-utilization`、或缩短 `--max-model-len`。

### 8.5 工具调用不生效

本地模型需要支持 function calling。Qwen3、Llama 3.1+ 等较新模型支持较好；老模型或量化过度的模型可能返回无法解析的结构。可先用 `--no-tools` 验证基础对话是否正常。

### 8.6 `pip install` 报 `externally-managed-environment`

Ubuntu 24.04 的 PEP 668 保护。本项目不需要装包；如需安装请先 `source .venv/bin/activate`，或对 vLLM 使用独立环境。

### 8.7 修改配置后没生效

配置在**进程启动时**读取。需重启 `server.py` 或重新执行 `agent.py`。

### 8.8 Web 页面打不开但服务在跑

确认访问端口是 `8010`（`server.py` 的 `--port`），并带上 `?token=`。仅访问根路径无令牌会返回 401。

## 附录 A：用 systemd 托管 vLLM

创建 `/etc/systemd/system/vllm.service`：

```ini
[Unit]
Description=vLLM OpenAI-compatible server
After=network-online.target

[Service]
Type=simple
User=<你的用户名>
WorkingDirectory=/home/<你的用户名>
ExecStart=/home/<你的用户名>/vllm-env/bin/vllm serve Qwen/Qwen3-8B-Instruct \
  --host 0.0.0.0 --port 8000 \
  --served-model-name qwen3-8b \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.90
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now vllm
sudo systemctl status vllm
journalctl -u vllm -f
```

## 附录 B：用 systemd 托管 Agent

`/etc/systemd/system/multi-model-agent.service`：

```ini
[Unit]
Description=Multi-model Agent Web UI
After=network-online.target vllm.service

[Service]
Type=simple
User=<你的用户名>
WorkingDirectory=/home/<你的用户名>/multi-model-agent
ExecStart=/usr/bin/python3 server.py --host 0.0.0.0 --port 8010
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now multi-model-agent
```

令牌可用 `sudo -u <用户> cat ~/.multi-model-agent/server.token` 查看。
