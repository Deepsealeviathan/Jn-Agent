# 多模型 Agent 项目文档

- 文档版本：1.0
- 适用代码：`agent.py` / `server.py` / `ui.html` 当前版本
- 运行环境：Linux（WSL）+ Windows 可选反向代理
- 访问方式：`http://localhost:8000/?token=<TOKEN>`

> 本文档已脱敏：不包含本机局域网 IP、访问令牌、API Key、GitHub 凭据或个人信息。所有示例地址统一使用 `localhost`。

---

## 1. 项目概览

多模型 Agent 是一个本地运行的通用智能体，提供命令行和 Web 两种使用方式。它可以在同一个对话中自由切换 Kimi、DeepSeek 等模型，调用工具操作本机文件与命令，并把每次调用的 Token 用量持久化统计。

核心能力：

- **多模型切换**：Kimi（Anthropic 协议）与 DeepSeek（OpenAI 兼容协议）共用一套对话。
- **工具调用**：执行命令、读写文件、列目录、发布下载文件、查询 Token。
- **Token 统计**：按请求、会话、模型、时间范围统计输入/输出/缓存命中。
- **多轮对话**：自动保存历史，WebUI 左侧导航栏可查看、置顶、删除。
- **思考过程**：模型返回 reasoning/thinking 时，页面以可折叠面板展示。
- **文件下载**：模型把文件放入下载目录后，页面顶部「文件下载」可直接获取。
- **请求约束**：能力询问先确认，避免未经确认直接生成长文浪费 Token。
- **安全确认**：执行命令、写文件可按三档权限模式确认。

技术特点：

- 后端仅使用 Python 标准库，无第三方运行时依赖。
- 前端为单个 `ui.html`，原生 HTML/CSS/JavaScript。
- 会话、Token 日志、下载文件均保存在用户目录，不依赖数据库。

## 3. 系统架构

```text
浏览器
  │  HTTP + Bearer Token
  ▼
Windows 侧 win_proxy.py :8000        （可选，便于 Windows 浏览器访问）
  │  反向代理
  ▼
WSL/Linux 侧 server.py :8010
  ├── ui.html                        静态页面
  ├── REST API                       会话、统计、下载、审批
  └── Agent 核心
        ├── 模型路由（Kimi / DeepSeek）
        ├── 工具执行（shell / 文件）
        ├── 会话上下文
        └── Token 统计
              ├── usage.jsonl
              └── conversations/*.json
```

请求流程：

1. 浏览器发送 `POST /api/chat`，携带 `session_id`、`message`、`model`、`approval_mode`、`turn_id`。
2. `server.py` 从 `SessionStore` 取出或创建会话，交给 `agent.turn()`。
3. Agent 组装系统提示词与历史消息，按模型协议调用上游。
4. 如果模型请求工具，Agent 执行工具并把结果追加到上下文，继续下一轮。
5. 最终回复、思考过程、工具事件、Token 用量返回给页面并写入磁盘。

## 4. 快速开始

### 4.1 环境要求

- Python 3.11 或更高版本（读取 TOML 密钥需要 `tomllib`）。
- 可选：Windows + WSL，用于浏览器访问与端口转发。
- 不需要安装数据库、Node.js 或 Python 第三方包。

### 4.2 命令行模式

```bash
cd ~/multi-model-agent
python3 agent.py                          # 交互模式
python3 agent.py -m kimi "解释这个报错"    # 单次调用并指定模型
python3 agent.py --list-models            # 查看模型与密钥状态
python3 agent.py --ping                   # 测试所有模型连通性
python3 agent.py --stats                  # 查看历史 Token 统计
```

常用交互命令：

| 命令 | 作用 |
| --- | --- |
| `/models` | 列出模型、协议、上下文长度、密钥来源 |
| `/model <别名>` | 切换模型 |
| `/usage` | 本次会话与历史累计 Token |
| `/context` | 当前上下文占用 |
| `/new` | 清空当前对话 |
| `/auto on\|off` | 开关自动确认 |
| `/tools on\|off` | 开关工具调用 |
| `/exit` | 退出 |

### 4.3 Web 模式

WSL/Linux 内启动后端：

```bash
cd ~/multi-model-agent
python3 server.py --host 0.0.0.0 --port 8010 --auto
```

Windows 侧把 `win_proxy.py` 复制到用户目录并启动转发：

```powershell
copy win_proxy.py %USERPROFILE%\agent_win_proxy.py
D:\anaconda\python.exe %USERPROFILE%\agent_win_proxy.py --listen-host 0.0.0.0 --listen-port 8000 --upstream-port 8010
```

访问：

```text
http://localhost:8000/?token=<TOKEN>
```

令牌来源：

1. 启动时 `--token` 显式指定；
2. 否则读取 `~/.multi-model-agent/server.token`；
3. 文件不存在时自动生成并写入。

也可以加 `&stats=1` 直接打开 Token 统计抽屉，加 `&history=1` 直接展开历史侧栏。

> 服务启动日志只显示 `localhost` 访问地址，不再输出本机局域网 IP。

## 5. 配置说明

### 5.1 `models.json`

主要字段：

| 字段 | 说明 |
| --- | --- |
| `default_model` | 默认模型别名 |
| `auto_approve` | 是否默认自动确认工具操作 |
| `max_tool_steps` | 单轮最大工具调用步数，默认 20 |
| `shell_timeout` | shell 默认超时秒数 |
| `system_prompt` | 系统提示词 |
| `usage_log` | Token 日志路径，默认 `~/.multi-model-agent/usage.jsonl` |
| `providers` | 上游提供商定义 |
| `models` | 模型别名定义 |

模型别名常用字段：

```json
"kimi": {
  "provider": "kimi",
  "model": "kimi-for-coding",
  "display": "Kimi K2.8 Preview",
  "max_context": 1048576,
  "max_tokens": 8192
}
```

提供商支持两种协议：

| 协议 | 请求地址 | 鉴权 |
| --- | --- | --- |
| `openai` | `POST {base_url}/chat/completions` | `Authorization: Bearer` |
| `anthropic` | `POST {base_url}/messages` | `x-api-key`、Bearer 或两者 |

### 5.2 本地覆盖配置（脱敏关键）

仓库中的 `models.json` 只保留脱敏后的地址，例如：

```json
"deepseek": {
  "protocol": "openai",
  "base_url": "http://localhost:8030/v1"
}
```

如果真实模型服务不在 `localhost`，在项目根目录创建 `models.local.json`，写入真实地址：

```json
{
  "providers": {
    "deepseek": {
      "base_url": "http://<你的模型服务地址>/v1"
    }
  }
}
```

`models.local.json` 已在 `.gitignore` 中，不会被提交。`agent.load_config()` 会把它深度合并到 `models.json` 之上，因此：

- 公开仓库/文档只出现 `localhost`；
- 本机运行仍能连到真实服务；
- 不要把手写真实 IP 的文件加入版本控制。

也可以用环境变量 `AGENT_LOCAL_CONFIG` 指定另一个覆盖文件路径。

### 5.3 密钥解析顺序

1. 环境变量 `api_key_env`（如 `KIMI_API_KEY`、`DEEPSEEK_API_KEY`）；
2. 配置中的 `api_key` 字段；
3. `api_key_from` 指向的外部文件，支持 JSON 路径与 TOML 路径。

默认复用本机已有登录：

- Kimi：`~/.kimi-code/credentials/kimi-code.json` 的 OAuth `access_token`；
- DeepSeek：`~/.kimi-code/config.toml` 中 `local-deepseek` 的密钥。

密钥不会打印到终端，也不会写入 Token 日志。

## 7. 工具与权限

### 7.1 工具列表

| 工具 | 作用 | 默认确认 |
| --- | --- | --- |
| `run_shell` | 执行 shell 命令，合并 stdout/stderr 与退出码 | 是 |
| `read_file` | 读取文本文件，默认最多 200,000 字节 | 视模式 |
| `write_file` | 覆盖或新建文件，自动创建父目录 | 是 |
| `list_dir` | 列出目录内容，最多 500 项 | 视模式 |
| `publish_download` | 把文件复制到下载目录 | 视模式 |
| `get_token_usage` | 查询会话与历史 Token 用量 | 否 |

工具输出上限：`run_shell` 最多回传 20,000 字符；网页端工具事件超过 4,000 字符会截断展示。

### 7.2 三档权限模式（WebUI）

| 模式 | 行为 |
| --- | --- |
| 始终询问 | 所有文件读取、写入、命令执行都需要用户确认 |
| 必要时询问 | 仅当 shell 命令包含删除/清空类操作时确认 |
| 完全自动 | 不询问，直接执行 |

「必要时询问」识别的危险操作包括 `rm`、`rmdir`、`unlink`、`shred`、`find -delete`、`truncate` 等。

CLI 默认使用 `standard` 模式：`run_shell` 与 `write_file` 需要确认。非交互单次调用默认拒绝需要确认的操作，除非加 `--auto`。

### 7.3 能力询问与长文生成约束

当用户只是询问能力，例如：

- “能否生成小说”
- “可以写文章吗？”
- “你会写代码吗”

Agent 会先简短确认，并询问主题、篇幅、风格、用途等参数，**不会直接生成正文**。

实现方式：

- 系统提示词要求确认性提问先回答再询问参数；
- `is_generation_inquiry()` 识别中英文能力询问；
- 命中后本轮禁用工具、输出上限压到 900 token，并追加临时系统约束；
- 如果模型仍输出超过 500 字，丢弃草稿并替换为固定确认话术，草稿不写入历史。

用户明确回复“开始写吧，写一篇 100 字科幻小说”后，恢复正常生成。

## 8. Token 统计

### 8.1 统计口径

- 输入、输出、缓存命中分别累计。
- Anthropic：输入总量 = `input_tokens + cache_read + cache_creation`。
- OpenAI：缓存命中来自 `prompt_tokens_details.cached_tokens`。
- 上游未返回 `usage` 时按字符估算：
  - 中日韩字符约 1.1 token/字；
  - 其他字符约 3.6 字符/token；
  - 记录标记 `"estimated": true`。

### 8.2 存储格式

`~/.multi-model-agent/usage.jsonl` 每行一条请求：

```json
{
  "ts": "2026-11-23T00:00:00+08:00",
  "session": "web-<会话ID>",
  "alias": "deepseek",
  "model": "DeepSeek-V4.1-Flash-1017",
  "prompt_tokens": 1200,
  "completion_tokens": 300,
  "cached_tokens": 800,
  "total_tokens": 1500,
  "estimated": false
}
```

### 8.3 WebUI 统计范围

| 参数 | 显示 |
| --- | --- |
| `24h` | 近 24 小时，按小时分桶 |
| `7d` | 近 7 天，按天分桶 |
| `30d` | 近 1 个月，按天分桶 |
| `90d` | 近 3 个月，按周分桶 |
| `all` | 全部，按月分桶 |

统计抽屉展示：总 Token、请求数、输入/输出/缓存、趋势图、按模型分布，以及历史累计。

### 8.4 模型自查

用户问“你用了多少 Token”时，模型调用 `get_token_usage` 返回真实数据，而不是猜测。

  "id": "<会话ID>",
  "title": "会话标题",
  "created_at": "2026-11-23T00:00:00+08:00",
  "updated_at": "2026-11-23T00:01:00+08:00",
  "model": "deepseek",
  "pinned": false,
  "usage": {

    "prompt_tokens": 1200,

## 10. HTTP API

除 `/healthz` 与下载链接外，所有接口都需要：

```http
Authorization: Bearer <TOKEN>
```

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | WebUI |
| GET | `/healthz` | 健康检查，无需令牌 |
| GET | `/api/models` | 模型列表、协议、上下文、密钥状态 |
| GET | `/api/stats?range=24h\|7d\|30d\|90d\|all` | Token 聚合统计 |
| GET | `/api/usage?session_id=` | 指定会话的 Token |
| GET | `/api/conversations` | 会话列表 |
| GET | `/api/conversations/<id>` | 会话详情与事件流 |
| POST | `/api/chat` | 发送消息并等待完整回复 |
| POST | `/api/conversations/<id>/pin` | 置顶/取消置顶，`{pinned: true}` |
| DELETE | `/api/conversations/<id>` | 删除会话 |
| GET | `/api/approvals?turn_id=` | 查询待审批操作 |
| POST | `/api/approvals/<id>` | 批准/拒绝，`{approved: true}` |
| GET | `/api/downloads` | 下载目录文件列表 |
| GET | `/downloads/<name>?token=` | 下载文件 |
| POST | `/api/reset` | 清空指定会话，`{session_id}` |

`POST /api/chat` 请求示例：

```json
{
  "session_id": "",
  "message": "你好",
  "model": "deepseek",
  "approval_mode": "necessary",
  "turn_id": "abcd1234"
}
```

响应包含 `session_id`、`answer`、`tools`、`usage.turn`、`usage.session`、`conversation` 等字段。工具事件中的 `output` 超过 4,000 字符会被截断。

## 12. 安全与脱敏

- **访问令牌**：所有 API 需要 Bearer Token；下载链接支持 `?token=`。
- **令牌存储**：`~/.multi-model-agent/server.token`，权限由系统用户控制。
- **自动模式风险**：`--auto` 或「完全自动」会跳过确认，只建议在可信环境使用。
- **密钥不落盘**：API Key 从已有凭据文件或环境变量读取，不写入日志。
- **配置文件脱敏**：
  - 仓库内 `models.json`、`agent.py` 默认只写 `localhost`；
  - 真实服务地址放在 `models.local.json`（已忽略提交）；
  - 文档不包含任何本机 IP、令牌、用户名或仓库地址。
- **公开仓库前检查**：

```bash
git status --short
git grep -nE '([0-9]{1,3}\.){3}[0-9]{1,3}' || true
git grep -nE 'ghp_|sk-|Bearer [A-Za-z0-9]' || true
```

如果发现真实地址或密钥，先移除并轮换密钥，再提交。

## 13. 故障排查

### 13.1 页面 401 / 无法连接

- 确认 URL 带 `?token=<TOKEN>`，或已在页面输入令牌。
- 确认 `server.py` 正在监听 8010，Windows 代理正在监听 8000。
- 检查 `~/.multi-model-agent/server.token` 是否与服务启动时一致。

### 13.2 模型 403 / 不可用

- `--ping` 检查连通性。
- Kimi 部分模型需要对应订阅；403 通常不是代码问题。
- 检查 API Key 是否过期；Kimi OAuth 令牌过期时重新登录 Kimi Code。

### 13.3 模型返回空内容

旧版本只在 `finish_reason == "length"` 时自动重试。实际出现过模型只返回思考内容、正文为空但 `finish_reason` 不是 `length` 的情况，导致页面显示“模型本次未返回内容”。

现已修复：

- 只要回复没有可见正文且没有工具调用，就自动关闭思考模式重试一次；
- 重试仍为空时，提示“模型本次没有返回可见内容，已自动重试仍未成功”；
- 服务日志会打印 `[提示] 模型返回空内容，关闭思考模式后重试一次…`。

如果仍频繁出现，建议切换模型、缩短上下文，或检查上游服务日志。

### 13.4 上下文过长

- 页面右上角会话胶囊或 `/context` 可查看上下文占用。
- 长对话可新建会话，或清理不必要的大工具输出。
- 接近 `max_context` 时，输出预算会被压缩，容易触发截断。

### 13.5 端口冲突

```bash
ss -ltnp | grep -E '8010|8000'
```

结束占用进程，或改用其他端口启动。

### 13.6 生成文档时不要依赖 python-docx

本项目的文档使用 Markdown，不需要安装 `python-docx`。在受 PEP 668 保护的系统中直接 `pip install` 会被拒绝，这也是此前一次空回复的诱因之一：模型尝试安装依赖失败后没有产出最终内容。

## 14. 已知限制

- 非流式响应：`/api/chat` 等模型完成后一次性返回，长任务等待时间较长。
- 会话保存在单个服务进程内，多进程部署需要额外的共享存储。
- 所有用户共享一个访问令牌，没有多用户权限体系。
- 工具在服务进程的工作目录执行；请从项目目录启动，避免误操作其他路径。
- 前端无构建步骤，修改 `ui.html` 后浏览器强刷即可生效。
